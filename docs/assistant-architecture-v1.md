# Интеллектуальный помощник ThunBudget — архитектура v1

## Цель
Добавить свободное текстовое и голосовое управление бюджетом, не меняя текущий дизайн и не перенося финансовую базу в облако.

## Архитектура
1. Android получает текст из поля ввода или локального распознавания речи.
2. Локальный обработчик исполняет простые известные команды и доступен офлайн.
3. Если команда сложная или неоднозначная, приложение отправляет в Supabase Edge Function только фразу и минимальный контекст (список категорий, локальную дату, необходимые агрегаты по запросу).
4. Edge Function вызывает выбранную LLM и возвращает структурированное намерение. Ключ провайдера хранится только в Supabase Secrets.
5. Android проверяет ответ по allowlist, показывает пользователю интерпретацию и только затем читает/изменяет локальные данные.
6. Supabase не хранит расходы и не становится источником финансовых данных.

## Контракт намерения
Поддерживаемые intent:
- add_expense, add_income
- query_remaining, query_spending, query_category_spending, query_overspending
- forecast
- update_expense, delete_expense
- unknown

Поля: intent, amount, category, title, date, period_start, period_end, target, confidence, missing_fields.

Даты и суммы валидируются приложением. Категория должна совпасть с локальным списком. Модель не получает права выбирать произвольные операции по внутреннему ID.

## Безопасность
- Все записи и изменения требуют отдельного подтверждения пользователя.
- Удаление требует отдельного подтверждения с указанием конкретной операции.
- Ответ модели — недоверенный ввод: allowlist intent, проверка диапазонов, дат, категорий и обязательных полей.
- Запросы чтения не должны изменять состояние.
- Не отправлять весь архив расходов. Передавать только минимум, необходимый для конкретного вопроса.
- При отсутствии сети или ключа модели остаётся доступен локальный режим.
- Ключ API не хранится в APK и не передаётся на устройство.

## Этапы
1. Контракт intent, локальная валидация и первый офлайн-парсер реализованы в feature-ветке. Текстовый диалог и голосовой ввод используют общий pipeline для поддерживаемых запросов. Добавлены unit-тесты на базовые русскоязычные команды.
2. Локальные команды чтения подключены к текущим данным расходов, категориям и отчётному периоду. Добавление дохода/расхода проходит через существующий экран предварительного подтверждения. Следом расширить команды записи и контекст диалога.
3. Текстовый диалог и контекст коротких уточнений; существующий экран «Обзор» не менять.
4. Supabase Edge Function + подключение LLM через серверный secret.
5. Голосовой ввод через тот же pipeline, что и текст.
6. Тестирование на неоднозначных фразах, офлайн-режиме и ошибочных ответах модели.

## Важное ограничение интеграции
Подписка ChatGPT не включает автоматически API-доступ для мобильного приложения. Для облачной интерпретации потребуется отдельный API-ключ выбранного провайдера; он будет храниться только в Supabase Secrets. До его настройки можно реализовать и проверить локальный слой.
